## ما يساعدك على تتبّعه

* الربح الفعلي المحقق بعد تحويل العملات الأجنبية بدلًا من الربح الورقي في تاريخ الفاتورة.
* ودائع العملاء والدفعات المقسّطة والأرصدة القائمة والتعرض الائتماني المتأخر.
* تكاليف تمويل الموردين وأثرها على ربحية المعاملة.
* موقف رأس المال العامل عبر النقد والمستحقات والالتزامات.
* خسائر العملات الأجنبية المخفية بين تنفيذ البيع وتحويل العملة.
* الربحية والسيولة وأداء التمويل على مستوى كل صفقة على حدة.

## لماذا بنيت هذا

كثير من شركات التجارة بين أوروبا وأفريقيا لا تعاني في الواقع من مشكلة في مسك الدفاتر.

بل تعاني من **مشكلة في رؤية القرار**.

قد تبدأ المعاملة النموذجية بشراء مخزون باليورو أو الدولار، وتمويل جزء من هذا الشراء عبر ائتمان المورد، وبيع المنتجات بالنايرا أو الشلن الكيني أو فرنك CFA، وتحصيل المدفوعات عبر ودائع وأقساط، وتحويل العملة المحلية في النهاية إلى يورو أو دولار.

على الورق، تبدو المعاملة مربحة.

في الواقع، غالبًا ما تُدمّر حركات أسعار الصرف وتأخر التحصيل وتكاليف التمويل والتسويات الجزئية الربحية قبل أن تدرك الإدارة ما حدث بأكثر من ذلك.

يحدث الفشل التحليلي لأن المعلومات المالية تُنظّم عادةً حسب الفئة المحاسبية:

* المشتريات،
* المبيعات،
* القروض،
* المدفوعات،
* العملات الأجنبية.

لكن قرارات الإدارة تُتخذ بحسب **المعاملة**، لا بحسب الحساب المحاسبي.

بنيت هذا المصنف كإطار استدلالي قابل لإعادة الاستخدام يعيد بناء كل معاملة عبر **معرّف صفقة** (Deal ID) مشترك، ما يسمح بتقييم دورة الحياة الاقتصادية الكاملة للتجارة كوحدة واحدة.

### مثال

| قبل                     | بعد                     |
| -------------------------- | ------------------------- |
| الشراء: €40,000          | الشراء: €40,000         |
| البيع: ₦85,000,000          | البيع: ₦85,000,000         |
| سعر صرف مفترض: 1 يورو = ₦2,000 | سعر الصرف الفعلي: 1 يورو = ₦2,450 |
| الربح المقدّر: €2,500   | الربح المحقق: -€3,800  |

بدون تسوية على مستوى المعاملة، تستنتج الإدارة:

```text
This deal was profitable.
```

بعد إعادة بناء تدفقات التسوية الفعلية:

```text
Currency depreciation erased the margin.
The transaction generated a loss.
```

إذًا هذا المصنف ليس مجرد قالب جدول بيانات.

بل هو **إطار تحليلي مُنتَج يعيد بناء الواقع الاقتصادي عبر عمليات تجارية متعددة العملات**.

## مشاكل التجارة متعددة العملات التي يحلّها

| المشكلة                                                | بدون هذه الأداة                                  | مع هذه الأداة                                     |
| ------------------------------------------------------ | -------------------------------------------------- | -------------------------------------------------- |
| خسائر تسوية العملات مخفية داخل الأرصدة المحاسبية | الأرباح الورقية تبقى مبالغًا فيها | التعرض المحقق وغير المحقق للعملات يصبح مرئيًا |
| تتبّع أقساط العملاء | الأرصدة القائمة يصعب تسويتها | المستحقات تُتابَع تلقائيًا بحسب معرّف الصفقة |
| تجاهل تكاليف تمويل الموردين | تكاليف التمويل تُدمّر الهوامش بصمت | تكاليف الفائدة تُخصّص لكل معاملة |
| رؤية رأس المال العامل | نقص النقد يظهر بشكل مفاجئ | النقد والمستحقات والالتزامات تُعرض معًا |
| تحليل الربحية عبر الحدود | الإدارة تعتمد على تقارير مجمّعة | الربحية تُحلّل على مستوى المعاملة |
| مراقبة التعرض الائتماني | العملاء المتأخرون يبقون غير مكشوفين | تحليل التقادم وتنبيهات الدفع تصبح مرئية |

## لمن هذا

هذا الإطار مصمم لـ:

* شركات الاستيراد/التصدير بين أوروبا وأفريقيا.
* متداولي السلع الذين يعملون عبر عملات متعددة.
* أصحاب المشاريع الصغيرة والمتوسطة الذين يمولون المخزون عبر ائتمان الموردين.
* مستشاري تمويل التجارة.
* المديرين الماليين الذين يديرون التعرض للعملات الأجنبية.
* الشركات التجارية العائلية التي تحتاج رؤية مالية تشغيلية.

هذا الإطار **غير مصمم** لـ:

* مشاريع استبدال أنظمة ERP.
* أنظمة محاسبية مؤسسية متعددة المستخدمين.
* تكاملات مصرفية آلية.
* عمليات خزينة عالية التردد.

لا يلزم أي خبرة في الجداول الإلكترونية.

افتح النسخة المتصفح أو مصنف Excel وابدأ تسجيل المعاملات فورًا.

## عن المشروع

أبني أدوات خفيفة لدعم القرار لحالات العمل التي فيها أجزاء متحركة أكثر من أن يحفظها المرء في رأيته في وقت واحد.

السؤال وراء كل مشروع هو دائمًا نفسه:

> **ما المعلومات التي يجب أن تتواجد في مكان واحد لاتخاذ القرار التالي بثقة؟**

إطار ربحية التجارة متعددة العملات هذا مثال واحد على هذا النهج: تقليل التعقيد التشغيلي إلى نموذج تحليلي قابل لإعادة الاستخدام بدلًا من بناء منصة برمجية أخرى.

#### الفخ 1 — الخلط بين ربح الفاتورة والربح المحقق

تم تنفيذ شراء بمبلغ €40,000.

حققت المبيعات ₦85,000,000.

افترضت الإدارة:

```text
EUR/NGN = 2,000
```

الربح المتوقع:

```text
€2,500
```

حدثت التسوية الفعلية بعد أربعة أشهر:

```text
EUR/NGN = 2,450
```

الربح الفعلي:

```text
-€3,800
```

| النهج الخاطئ                             | النهج الصحيح                            |
| ------------------------------------------ | ------------------------------------------- |
| الربح محسوبًا بسعر صرف الفاتورة | الربح محسوبًا بسعر التسوية الفعلي |
| تجاهل توقيت تحويل العملة | إعادة بناء دورة حياة المعاملة الكاملة |

<details>
<summary>منطق الصيغة</summary>

```excel
Actual Profit =
Realized FX(A)
+ Unrealized FX(B × Closing Rate)
- Purchase Cost(A)
- Interest Cost(A)
- Direct Expenses(A)
```

</details>

---

#### الفخ 2 — تجاهل تكلفة تمويل المورد

القرار:

```text
Supplier financing increased purchasing capacity.
```

الافتراض الخفي:

```text
Financing cost is negligible.
```

مثال:

| البند      | القيمة    |
| --------- | -------- |
| رأس المال | €100,000 |
| المعدل      | 18%      |
| المدة  | 180 يومًا |

تكلفة الفائدة:

```text
€8,877
```

بدون تخصيص تكلفة التمويل:

```text
Deal appears profitable.
```

بعد التخصيص:

```text
Deal margin becomes negative.
```

<details>
<summary>منطق الصيغة</summary>

```excel
Interest =
Principal
*
Annual Rate
*
Days Outstanding
/
365
```

</details>

---

#### الفخ 3 — قياس السيولة بالنقد وحده

القرار:

```text
Cash balance indicates healthy liquidity.
```

المشكلة الخفية:

```text
Receivables and debt obligations ignored.
```

مثال:

| البند          | المبلغ   |
| ------------- | -------- |
| النقد          | €60,000  |
| المستحقات   | €180,000 |
| دين المورد | €240,000 |

رؤية النقد:

```text
Healthy.
```

رؤية رأس المال العامل:

```text
Negative €0.
```

الأعمال معرضة بالكامل لتأخر التحصيل.

<details>
<summary>منطق الصيغة</summary>

```excel
Working Capital =
Cash
+ Receivables
- Payables
```

</details>

### سيناريو مثال

موزّع يشتري مولّدات كهربائية من أوروبا.

#### المدخلات

| المتغير         | القيمة        |
| ---------------- | ------------ |
| معرّف الصفقة          | DEAL-24017   |
| الشراء         | €52,000      |
| التمويل        | €30,000      |
| الفائدة         | 15% سنويًا   |
| البيع             | ₦120,000,000 |
| ودائع العملاء | ₦30,000,000  |
| التحصيل النهائي | ₦90,000,000  |
| سعر صرف التسوية    | 2,420        |

#### الحسابات الوسيطة

| الحساب          | النتيجة  |
| -------------------- | ------- |
| اليورو الفعلي المسترد | €49,587 |
| مصروف الفائدة     | €1,973  |
| المصروفات التشغيلية   | €2,400  |
| الربح الصافي           | -€6,786 |

#### التفسير

لاحظت الإدارة مبدئيًا:

```text
Large nominal sales volume.
```

وكشف النموذج التحليلي:

* انخفاض قيمة العملة،
* تكاليف التمويل،
* تأخر التحصيل،

والتي دمرت الربحية مجتمعة.

#### التوصية

```text
Reduce customer credit period.
Increase deposit requirements.
Hedge currency exposure.
Reduce supplier leverage.
```

#### أثر القرار

لم تكن المشكلة في أداء المبيعات.

بل كانت المشكلة في بنية المعاملة.
